### 0.3 Legend

Cell values (exactly): **Yes / Partial / No / N-A / NV**.

* **Yes** = implemented and traced to a report section, issue id, or a file opened.
* **Partial** = implemented but with a documented defect, or implemented for only some sub-flows / routes of the family.
* **No** = not implemented, or implemented in a way the reports show is non-functional or absent.
* **N-A** = the question does not apply to the family (for example delete on a read-only dashboard, pagination on a single-class grid, authentication on the pre-auth login).
* **NV** = not verified: the reports say so, or no part traced it. I did not guess.

Q columns (identical order in every table):

| Q | Meaning used |
|---|---|
| Q1 Menu exists | A menu / registry entry exists in code (`routeMapper.ts`, `module-screens.generated.ts`, Header dropdown). Live `tblmenumaster` rows are NV for every family (no DB access), so Yes means "code-defined or seeded in migrations". |

Status class (exactly): **Complete / Mostly complete / Partially complete / Stub / Broken / Missing / Deprecated / Unknown-NV**. The class judges *function*. **(+)** after a class means at least one open **Critical** confirmed security/integrity issue in the family (the class is not lowered for it; the risk is carried by the issue ids). Broken = the core flow does not work or its integrity is defeated. Stub = UI/shell without a real backend or with mock/in-memory behaviour.
