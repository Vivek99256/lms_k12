## Legend and how to read the matrix

* **One row = one feature** (a menu entry or a money / identity / PII flow). Trivially identical CRUD screens are grouped into one row and listed in braces, e.g. `app/hostel/{hostel_master,building_master,...}/page.tsx`. Row ids `TM-nnn` are new and only for cross-reference.
* **UI (page path)** = file under `D:\lms_k12\app` (page.tsx unless a component is named). **Route** = Next route as listed in `part09-data-frontend-routes.md` plus the legacy menu link (`tblmenumaster.link`, e.g. `fees_collect.index`) where a report or `app/data/routeMapper.ts` states it; the live `tblmenumaster` rows themselves are NOT VERIFIED (remote DB, not read). `[V1-deferred: hidden from sidebar in uncommitted WT]` marks routes whose prefix is in the working tree's `V1_DEFERRED_ROUTE_PREFIXES` (`lib/roadmap/index.ts`); it changes what the sidebar advertises, not what the backend allows.
* **API (method + URL)** = the Laravel URL (as declared in `routes/*.php`; each Laravel URL was resolved against the route inventory CSV) or `Next <METHOD> /api/...` for a Next route handler (`app/api/**/route.ts`), `EXT` for a third-party host. **Controller** = `Class@method` resolved from the CSV (up to 6 shown; resource routes show the resource class) or the Next `route.ts` file; `none - ...` where no backend exists.
* **Service** = `App\Services|Domain|Support` classes imported by the resolved controller(s) (source scan). `-` = the controller imports none, i.e. logic is in the controller / `Helper.php`, not that a service is missing from the flow. **Model** = Eloquent models imported (`use App\Models\...`) by the controller(s) - an import can be unused; `DB::table (no model)` = controller uses the query builder directly; `-` = no backend or no DB access. Both are unions over the resolved controllers (a merged row can show classes from several endpoints). `NV` = not verified.
* **DB (tables)** = tables named by the reports (part02..08 and 10) or found by the source scan; `(names NV)` / `(NV per table)` where a report did not trace them.
* **Permission** starts with the enforcing mechanism: `none` (no route middleware and no in-controller JWT/rights check), `route middleware` (e.g. `api.session` = valid JWT hydrates the session; `staff.only` = blocks only Student/Parent profile names, not RBAC; `pal.auth`; `brain.*`; `McpAuth`; `lms.auth`/`perm:` = warn-only unless `LMS_API_AUTH_ENFORCE=true`, default false), `in-controller` (JWT decoded and/or rights checked inside the controller), `menu-rights` (`session` + `check_permissions`: rights keyed on route name -> `tblmenumaster.link`, bypassable with a client `submit=Search` field and fail-open when the route name has no menu row - AUTH-02/BE-10), `client-only` (browser check only, no server enforcement point), `mixed`. `// ALSO:` separates the weaker/stronger mechanisms of a merged row; the most severe is listed first.
* **Tenant Scope** starts with `token-bound` (`sub_institute_id`/user/profile taken from the verified JWT), `client-trusted` (request body/query/header value wins, or the JWT is only checked for validity), `none` (no tenant filter at all, or platform-wide/global data), `NV` (not verified) or `n/a` (no data-bearing backend call, or pre-auth). `n/a` is an added value used only where the other four cannot apply.
* **Tests** = the actual test file(s) or `none` (per part03 section 7: all 42 frontend tests are `lib/**` unit tests; no route-handler, component or E2E test exists; Laravel has 124 test files). Backend test files are cited by directory/file-name match to the feature and are marked `(name-matched; contents NV)` where the reports did not state what they cover; a cited test never implies the risky path is covered unless the cell says so.
* **Status** = Complete / Mostly complete / Partially complete / Stub / Broken / Missing / Deprecated / Unknown-NV as in the shared brief. It follows the owning report's module inventory (part02/04/05/06/07/08/10); missing authorization is shown in the Permission and Tenant columns and is not by itself a reason for `Broken`, except where the owning report itself labels the flow `Broken` or `Broken (security)` (part02, part06 and part10 do this for a few families). Where two reports disagree on the same flow the row follows the report that traced the flow end to end. `Missing` = backend exists without a Next UI (or the reverse is stated in the row); `Stub` = UI/route that does nothing real. **Statuses describe the audited baseline** (Laravel commit `0bd66fc3b`; frontend commit `771e660`); they mean "open at baseline".

## Known limits of this matrix

* `DB (tables)` for many Laravel-side rows is "NV per table": the reports traced controllers, not every table; the live database was not accessed and migrations are documented as drifted from the live schema (project memory), so table/column presence is what the code and migrations say.
* Service and Model columns are a source scan of `use` statements in the resolved controllers; a controller that references a model by fully-qualified name in code, or delegates to `Helper.php`, will show `-` or `DB::table (no model)`.
* Merged rows (marked by "and"/lists in the Feature cell) report the union of their endpoints; where the endpoints differ in enforcement the Permission and Tenant cells list all variants with the most severe first (`// ALSO:`).
* The frontend has no `middleware.ts`/`proxy.ts` and no layout-level auth check (AUTH-16), so for every row the "UI gate" is at most a client-side convenience; the Permission column describes the server side only.
