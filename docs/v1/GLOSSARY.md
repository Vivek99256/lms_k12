# Glossary

Last updated: 2026-11-04
Generated from commit: `8fe500dc` (frontend) / `86261072` (backend)

Terms used throughout the Scholar Suite v1 Product Bible. When a term is specific to one product it is marked with the product tag.

---

## A

**Academic Term**
A subdivision of an academic year (e.g. Term 1, Term 2, or Semester 1). Stored in `tblacademictermmaster`. All fee, attendance, and timetable records are scoped to a term.

**Academic Year**
The annual cycle (e.g. 2025-26). Stored in `tblacademicyearmaster`. The active year is kept in `selectedAcademicYear` localStorage key; changed via the Header year switcher.

**Admission**
The workflow by which a prospective student becomes an enrolled student. Stages: Enquiry → Registration → Admission Form → Confirmation. `[core]`

**AI Stack**
Per-module configuration screens that let an admin enable or disable AI capabilities for a module. Built by `build-ai-stack-screens.tsx`. `[shared]`

**Alumni**
Former students who have left the institution. Managed in the Alumni module under Scholar Core. `[core]`

---

## B

**Bearer Token**
The JWT issued on login, stored in `userData.user_token` in localStorage. Sent as `Authorization: Bearer <token>` on every API call via the patched `window.fetch`.

---

## C

**CCB**
See *Scholar CCB*.

**Client**
The top-level tenant entity in a multi-school deployment. One client can have multiple institutes (sub-institutes). `client_id` is the top-level key.

**Collect Fee**
The act of recording a fee payment for a student. The primary operation in the Fees module. `[core]`

**Concession**
A fee reduction or waiver granted to a student. Requires workflow approval. `[core]`

**CTD (Carry To Date)**
Cumulative total of amounts collected up to a point in time. Used in fee reports.

---

## D

**Defaulter**
A student with an outstanding (overdue) fee instalment. The scheduler scans for defaulters daily.

**density**
UI density mode: comfortable / cozy / compact. Controlled via `data-density` attribute on `<html>`. Affects padding and font sizes but not layout.

---

## E

**Enquiry**
The first stage of the admissions funnel: a prospective student or family expresses interest. `[core]`

**ERP**
Enterprise Resource Planning. Scholar Core is the ERP layer of the platform.

---

## F

**FCM**
Firebase Cloud Messaging. Used to send push notifications to the K12 mobile app. Tokens stored in `gcm_users` table.

**Fees**
Collective term for tuition, transport, hostel, and other charges levied on students.

**Fees Structure**
The template that defines which fee heads apply to which class/batch for an academic year. `[core]`

---

## G

**GR No**
General Register Number. The unique admission number assigned to a student at the time of admission.

**Group Rights**
Menu access granted to an entire user profile (role). Stored in `tblgroupwise_rights`. See [rbac.md](./_shared/rbac.md).

---

## H

**H5P**
An open-source framework for creating interactive HTML5 content (quizzes, videos, presentations). Used in Scholar Learn for interactive learning content. `[learn]`

**Handoff Ticket**
A single-use token generated by the K12 mobile app that the WebView exchanges for a full session. Prevents raw JWT from being passed in URLs.

---

## I

**Individual Rights**
Menu access granted to a specific user, overriding their group rights. Stored in `tblindividual_rights`. See [rbac.md](./_shared/rbac.md).

**Institute / Sub-Institute**
A school campus or branch under a client. `sub_institute_id` scopes all data to one institute.

**Instalment**
A scheduled portion of a fee. A fee structure can have multiple instalments per year (e.g. quarterly).

---

## J

**JWT (JSON Web Token)**
The authentication credential issued on login. Validated server-side using `LARAVEL_JWT_SECRET`. Stored in `userData.user_token`.

---

## L

**Laravel**
The PHP 8.2 framework backing the Scholar Suite API. Runs at `https://dev.triz.co.in` (development). Source at `F:\xampp\htdocs\next_lms_erp`.

**LMS**
Learning Management System. The online course delivery layer of Scholar Learn. `[learn]`

**localStorage**
Browser key-value store used to persist session data across page loads. Keys: `auth`, `menuContext`, `userData`, `selectedAcademicYear`, `selectedAcademicTerm`.

---

## M

**Menu Master**
See *tblmenumaster*.

**Module**
A functional area of the product (e.g. Fees, Attendance, Admissions). Each module has its own set of screens and API controllers.

**Multi-tenant**
Scholar Suite serves multiple schools from a single deployment. Each school is a *client*; each campus is a *sub-institute*. All data is scoped by `sub_institute_id` and `client_id`.

---

## N

**NACH**
National Automated Clearing House. Used for recurring fee collection via bank mandate. `[core]`

---

## P

**PAL**
Personalised Adaptive Learning. An AI-driven layer within Scholar Learn that adapts content difficulty to each learner. `[learn]`

**Platform Services**
The shared infrastructure layer: Notification, Scheduler, Workflow, Audit, Event Bus, Document, Integration, RBAC. Configured via `config/platform_services.php`.

**Profile**
A named user role (e.g. Teacher, Accountant, Principal). Defined in `tbluserprofilemaster`. Menu rights are granted per profile.

---

## R

**RBAC**
Role-Based Access Control. In Scholar Suite, menu visibility is controlled by three tables: `tblmenumaster`, `tblgroupwise_rights`, `tblindividual_rights`. See [rbac.md](./_shared/rbac.md).

**Receipt**
A document issued after fee collection confirming payment. Auto-generated and emailed/WhatsApped to the parent.

**Registry**
Used in two contexts: (1) the AI capability registry in `packages/ai-intelligence-core/src/registry.ts`; (2) the Platform Services registry in `config/platform_services.php`.

---

## S

**Scholar CCB**
Scholar Competency & Career Builder. The HR, payroll, competency, and career development product.

**Scholar Compass**
The career counseling and college admission guidance product.

**Scholar Core**
The main school ERP: fees, admissions, students, attendance, exams, library, hostel, transport, etc.

**Scholar Insight**
The enterprise analytics and AI intelligence product.

**Scholar Learn**
The LMS and adaptive learning product: online courses, H5P content, PAL.

**Scholar Suite**
The full platform: Core + Learn + CCB + Insight + Compass.

**SessionContext**
The TypeScript type in `lib/erp-client.ts` that holds the runtime session: `{ baseUrl, token, subInstituteId, syear, userId, termId, isAdmin }`. Built from localStorage on every API call.

**SQAA**
School Quality Assurance & Accreditation. A module under Scholar Core for managing quality processes and inspection readiness. `[core]`

**SSE**
Server-Sent Events. The streaming transport used by the AI chatbot (`/api/ai/ask/stream`). Translated to Vercel AI SDK format by the Next.js proxy.

**Sub-Institute**
See *Institute*.

**Super Admin**
A user with `is_admin=1` and `sub_institute_id=0`. Has access to all institutes under a client.

**syear**
The numeric academic year identifier (e.g. `2526` for 2025-26). Used as a query parameter on most API calls.

---

## T

**tblmenumaster**
The authoritative menu catalog table. Every screen in the platform must have a row here before it becomes visible to any user.

**Term**
See *Academic Term*.

**Timetable**
The weekly schedule of classes and teachers. `[core]`

---

## U

**ULU**
Unit Learning Unit (or Unique Learning Unit). The atomic content block in the PAL system. `[learn]`

**User Profile**
See *Profile*.

---

## W

**Workflow**
An approval chain that pauses a business process (e.g. fee concession, result publish) until authorised users sign off. Defined in the Platform Services registry.

---

## Z

**Zero-trust fetch**
The pattern where `installErpAuthFetch()` patches `window.fetch` to inject the Bearer token on all API calls, so no component needs to manually add auth headers.
