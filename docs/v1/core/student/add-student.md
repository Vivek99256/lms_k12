## 1. Purpose & users
Creates a new student record and an active academic-year enrollment in one step. Used by admin or admissions staff at the time of a new student joining. The form auto-generates the GR (enrollment) number so staff cannot accidentally reuse one.

## 2. Screens
**Add Student form** (`/student/add_student`)
Single-page form with cascading dropdowns (Section → Standard → Division) and personal fields. Shows a success or error banner after save.

### Business rules
- GR No. is auto-generated by the backend (`student-registration/next-enrollment-no`). If a duplicate-GR error is returned, the frontend retries up to 3 times with a fresh number.
- Mobile must be exactly 10 digits; non-numeric characters are stripped as the user types.
- The `enrollment_no` field is `unique` in `tblstudent` (migration `2026_09_01_000001_add_unique_enrollment_no_to_tblstudent.php`).
- Section/Standard/Division dropdowns cascade: each one clears on change of its parent.

## 4. User flows

**Happy path**
1. Navigate to Student → Add Student.
2. Select Section → Standard → Division. GR No. auto-fills.
3. Fill in required personal fields.
4. Select Blood Group, Gender, Student Quota. Optionally select House.
5. Click "Save Student". Success banner shown; form resets.

**Duplicate GR retry**
1. Backend returns "GR no. already exists".
2. Frontend fetches a new GR No. and retries (up to 3 attempts) automatically.
3. If all 3 attempts fail, an error banner is shown.

## 6. APIs
| Method | Endpoint (via proxy) | Auth | Request | Response | Errors |
|---|---|---|---|---|---|
| GET | `student-registration/metadata` | Session token | Academic year params | `{ quotas: [], houses: [] }` | 400 if session invalid |
| GET | `student-registration/next-enrollment-no` | Session token | Academic year params | `{ enrollment_no: "..." }` | 500 if sequence fails |
| POST | `student-registration` | Session token | Form-encoded student fields | `{ status: 1, message: "Student created." }` | 422 if GR duplicate, 400 validation error |

All calls go through `/api/proxy` (Next.js thin proxy → Laravel).

## 10. Known issues, limitations & FAQs
- The GR number is read-only; there is no way for staff to override it on this form. If the auto-generated number is wrong, it must be corrected via Bulk Update or backend.
- The form does not support a photo upload at creation time; photo is captured separately via Face Attendance setup.
- `password` column in `tblstudent` stores plain text (varchar 50) — this is a legacy field not used for authentication in the Next.js app; login goes through the JWT system.
- No inline address auto-complete or pincode validation.

**FAQ:** *Can I change a student's GR number after creation?* — Not via this form; use Bulk Update or the Laravel admin.

## 11. Sales notes

- Auto-generated GR numbers prevent duplicate-entry errors common in spreadsheet-based schools.
- Enrollment is created in the same transaction — no two-step process.
