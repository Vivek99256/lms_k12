## 1. Purpose & users
Enables parents and students to pay fees online via a payment gateway without coming to the school. Admin can configure gateway settings; accountants can view and confirm online payments; parents pay via a shareable payment link.

## 2. Screens

### Online Fee Collection (`/fees/online_fees_collect`)
Admin/accountant view of pending and completed online fee transactions. Shows gateway-wise status, allows manual confirmation of payment.

### Online Fee Settings (`/fees/online-fees-settings`)
Configure the payment gateway credentials and rules (gateway name, merchant ID, keys — stored server-side, never exposed to frontend).

### Online Payment Gateway (`/fees/online-payment/[gateway]`)
Per-gateway payment processing page (gateway slug in URL).

### Public Payment Page (`/pay/[code]`)
Public, unauthenticated page. Parents open this link (shared by school) to pay fees. The `code` is a one-time or reusable payment token generated by the backend.

## 3. Features & business rules

**`online_fees_settings` stored fields (from `tblfeesConfigModel` and `online_fees_settigs_controller`):**

| Field | Type | Notes |
|---|---|---|
| `cms_client_code` | varchar | NACH/gateway client code |
| `account_to_be_credited` | varchar | Bank account number |
| `nach_account_type` | varchar | SB / CA |
| Gateway credentials | — | Stored server-side only; never in frontend |

**Online fees split (`online_fees_split_controller`):** Splits a collected online payment across multiple fee heads according to the breakoff schedule.

**Receipt reprint (`receipt_reprint_api_controller`):** Allows re-printing an online payment receipt after the fact.

**Reconciliation (`reconciliation_status_api_controller`):** Checks gateway reconciliation status — matches bank statement to collected amounts.

**`confirmOnlineFeesController`:** Marks an online payment as confirmed once gateway callback is received.

**Public payment flow:** `/pay/{code}` is served without authentication. The `code` is validated against a backend record before allowing payment.

## 4. User flows

**Happy path — parent pays online:**
1. School admin generates/shares a payment link for a student.
2. Parent opens `/pay/{code}`.
3. Frontend calls `public_fee_pay_api_controller` to validate the code and get fee details.
4. Parent selects amount and confirms.
5. Gateway redirect — payment processed externally.
6. Gateway callback → `confirmOnlineFeesController` → marks payment confirmed in `fees_collect` with `payment_mode = 'Online'`.
7. SMS/email receipt sent if configured.

**Happy path — accountant views online payments:**
1. Navigate to `/fees/online_fees_collect`.
2. Filter by gateway, date range.
3. View pending / completed transactions.
4. Manually confirm if auto-confirmation failed.

**Reconciliation:**
1. After bank statement download, run reconciliation via `reconciliation_status_api_controller`.
2. Mismatches flagged for review.

## 5. Data model

**Tables involved:**
- `fees_collect` — final confirmed payment row (`payment_mode = 'Online'`)
- `fees_online_*` — staging tables for gateway transactions (exact table names in migration `create_fees_online_*`)
- `fees_config_master` — gateway config (CMS code, account)

**Key online-fees staging columns (from migrations, exact names TBD):**
- `gateway_ref_no` — gateway transaction reference
- `payment_status` — pending / success / failed
- `gateway_name` — which gateway processed it
- `student_id`, `syear`, `sub_institute_id`

## 6. APIs

| Method | Endpoint | Auth | Notes |
|---|---|---|---|
| POST | `/fees/online_fees/collect` | JWT | Trigger online collection |
| GET | `/api/online-fees-settings` | JWT (Admin) | Get current gateway config |
| POST | `/api/online-fees-settings/update` | JWT (Admin) | Update gateway config |
| POST | `/api/online-fees-payment` | JWT or public token | Process payment |
| GET | `/pay/{code}` | None (public) | Public payment page |

## 10. Known issues, limitations & FAQs

- Gateway credentials must NEVER be in `NEXT_PUBLIC_*` env vars — they are server-only.
- `online_fees_settigs_controller` has a typo ("settigs") — preserved for backward compatibility; the API controller extends it unchanged.
- No multi-gateway support in v1 (one gateway per institute).

**FAQ:**
- *"Parent says they paid but it doesn't show"* — check the gateway callback was received; run reconciliation.
- *"Receipt not generated for online payment"* — confirm `confirmOnlineFeesController` ran successfully; check `fees_collect.payment_mode`.

## 11. Sales notes

**Selling points:**
1. Parents pay from home — no queue at school.
2. Auto-confirmation via gateway callback — zero manual work for 90% of payments.
3. Public `/pay/{code}` link works without login — lower friction for parents.

**Demo flow (3 steps):**
1. Show online fee settings — gateway config (masked).
2. Open the public payment link in an incognito window.
3. Show how payment appears in the online collection list after confirmation.

**v1 partial:** Multi-gateway support is not implemented.
